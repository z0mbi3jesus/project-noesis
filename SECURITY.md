# Security and sensitive reports

Do not put credentials, private source, personal data, or exploitable security
details into a public issue or pull request.

If the repository offers **Security → Report a vulnerability**, use that private
channel. Otherwise, open an issue requesting a private contact method without
including sensitive details, and wait for the project lead to establish one.
No private contact address or response-time commitment is currently published.

Diagnostic exports may include entered text, local paths/usernames, session IDs,
stack traces, and other experimental data. Review every attachment before sharing.
Reports are not sent automatically by the current application.

Tester downloads are pending. If reviewed builds are published later, use the
project's official GitHub Releases. Checksums identify matching files; they do not
replace code signing or an independent security review.
