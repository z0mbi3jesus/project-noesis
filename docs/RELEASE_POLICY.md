# Releases and distribution

Effective: October 15, 2026

**Tester downloads are currently on hold.** This repository is a public research
and participation hub. Its automatic source archives are documentation packages,
not application installers.

Before an application release, the project lead must approve the included
capabilities, disclosed materials, licensing/distribution terms, and final artifacts.
Executable packaging or obfuscation is not a guarantee that implementation details
cannot be recovered.

## Release information

An approved tester release should identify:

- Version, supported operating systems, installation/launch steps, and known issues.
- Included benchmarks, supplied mechanisms, and scientific limitations.
- Applicable distribution terms and required third-party notices.
- Data locations, diagnostic/export behavior, and relevant privacy guidance.
- Actual validation performed, remaining manual checks, and a checksum for each asset.
- Whether code signing was used; a checksum alone does not establish trust or safety.

Release assets must be prepared from a controlled private checkout and reviewed
individually. Do not upload development folders, Git history, credentials, raw
personal data, or internal research records as release assets. Public build logs
and workflows must not inadvertently disclose the private implementation.

## Status and support

An experimental release is not a production, safety-critical, medical, or other
high-stakes decision system. No release date, compatibility guarantee, maintenance
term, or security-response deadline is promised by this policy.

If a release is withdrawn or superseded, communicate the reason and scope when
possible. Do not describe withdrawal as revoking copies already downloaded.
